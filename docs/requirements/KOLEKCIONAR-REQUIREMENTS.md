# Kolekcionar.com requirements

## High Level Requirements

1. Kolekcionar.com will be a web site that allows users to buy and sell modern collectibles. It will specifically serve only Serbian market, but it should be easily expandable to neighboring countries in Balkan region. The site will be accessible in Serbian (Latin and Cyrillic) and English.
2. Initially it will be just for me to sell my own collectibles.
3. Scope of modern collectibles: diecast cars, Trading Card Game's cards, Funko figures, action figures, and similar collectibles.
4. Main modules:
   1. Auth module - user registration, login, logout, password reset
   2. Master Data Management module of all collectibles. It will contain a catalog of modern day collectibles. Admin will be able to enter attributes for each category of collectible. We will setup pre-defined categories, sub-categories, manufacturers, brands, sub-brands, attributes, and attribute values for the most common collectibles. User will be able to add/edit/delete categories, sub-categories, manufacturers, brands, sub-brands, attributes, and attribute values.
      1. Category (diecast, TCG card, figure, ...)
      2. Sub-category (diecast scale (1:16, 1:64, 1:43, 1:24, 1:18, 1:12, 1:8, ...), TCG card set (Magic: The Gathering, Pokemon, Yu-Gi-Oh!, ...), Funko figure series (POP!, ...), action figure series, ...)
      3. Manufacturer (mattel, Majorette, GreenLight, ...)
      4. Brand (Hot Wheels, Matchbox, Corgi, Pop!, ...)
      5. Sub-brand (Hot Wheels Premium, Hot Wheels mainline, Hot Wheels id, ...)
      6. Lot - single item or grouped set of items. Lot will have its own attributes, like number of items, etc. It will be used for tracking purchase prices of collectibles in the lot against selling price, so that user can determine profitability of the lot. Lot will not have categories, sub-categories, manufacturers, brands, sub-brands, attributes, etc. It will be just a grouping of items. Lot owner will have to select at least one attribute to be basis for lot profitability tracking - default profitability measurements are buying and selling prices.
      7. Each category of collectibles have different attributes. For example, diecast cars have attributes like scale, type, series, model, version, etc. TCG cards have attributes like set, rarity, type, etc.
      8. MDM module will be a part of Admin Console. Admin user will be able to add/edit/delete categories, sub-categories, manufacturers, brands, sub-brands, attributes, etc.
      9. MDM module will be connected to web scraping module, which will scrape web for catalog information needed for MDM module. It will try to register new collectibles or update existing ones. It will scrape metadata (name, description, photos, etc.) from various online resources. It will also scrape all images of the collectibles and attempt to assign them to the correct collectible.
      10. Web scraping will heavily use LLM AI models to refine scraped data, detect invalid information and assign images to the correct collectible. It will also use image similarity algorithms to find duplicate or similar images. It will also use fuzzy matching algorithms to find similar names of collectibles.
      11. Scrapers will also scrape for online marketplaces and sales of collectibles to get historical sales data. This information will be used to calculate the value of collectibles and to provide users with price recommendations when they are listing their collectibles for sale. Prices will need to be adjusted to Serbian market, since shipping, customs, and taxes are heavily increasing the prices of legally obtained collectibles. Also Serbian market is not developed at all, and it is hard to determine local fair pricing for collectibles since no platform exists that could provide this information. My goal is to make the most comprehensive database of collectibles in Serbia and region.
      12. Same collectible can have different versions or color or design variations. We wil track all of these in our platform. Such collectibles can have the came manufacturer's SKU number but different designs in different years, for example. We need to be able to capture all of such corner cases. Example for Hot Wheels: they produce same model of car in different years with different designs. We need to be able to capture all of these different designs and variations.
      13. MDM module will have powerful search across all attributes. It should allow admins to search for collectibles based on any attribute, and also combinations of attributes. This functionality will be available for users as well when they add a new collectible in their catalog.
   3. Collection module - allows users to create collections and add collectibles to them. It will also allow users to mark collectibles as "wishlist" (want to buy) and "owned" (already have). It will also allow users to create wishlists of collectibles they want to buy, and also to create lists of collectibles they have for sale.
   4. Listing module - allows users to list collectibles for sale. It will include fields for price, description, photos, etc. Users will be able to list only collectibles that are in their catalog. This functionality will be available only for members who have paid their monthly membership fee.
   5. Order module - allows users to buy and sell collectibles. It will include fields for price, description, photos, etc.
   6. Payment module - allows users to pay for collectibles. This is nice to have but will only be applicable for my own collectibles - we cannot sell other people's collectibles.
   7. Shipping module - allows users to ship collectibles. This is nice to have but will only be applicable for my own collectibles.
   8. User Profile module - allows users to manage their profile information, including name, email, password, preferences, favorite collectible types, etc.
5. This platform tagline will be in line of - "we allow you to earn and collect at the same time."
6. Monetization strategy is to have monthly membership which will allow users to list their collectibles for sale.
7. Creating a personal collection will always be free. Collections will be shareable with public.
8. All web scarped data will be available publicly for use by other members to create catalogs or list their items for sale.
9. Web scraping will be legally done, as much as possible, and as much as possible it will use public APIs. It will be done with respect to robots.txt and terms of service of scraped websites. Any website that does not allow scraping will be excluded from web scraping. For image scraping, it will be used only from domains that allow image scraping and link back to the original source.
10. Web scraped images are subject to copyright and cannot be visible on our web site. They will be visible only to admin. If admin wants to use these images on our web site, admin needs to get permission from the copyright holder. My intention is to create such database of images that will be open for use by our members to create their own catalogs and list their items for sale.
11. For now, all MDM data will be used only by me to populate my collection of collectibles. In the future, all MDM data will be available for all members to use in their own collections.
12. Any content (metadata or images) that web scraping module finds will go into Change Request Queue, where it will wait for Admin approval to be included in MDM database. Any new model metadata, metadata update or image addition or update will need to go through approval process. Admin will be able to approve or reject any change request.
13. Collector with the catalog does not have to be a seller as well.
14. Collections can be grouped in "standard" ways by existing attributes, but collector can also group collectibles in their own groups. Example: collector has a lot of Hot Wheels cars from 1980. He can group them in "Hot Wheels 1980" group. Also he can group them by color, for example "Red Hot Wheels cars from 1980" or "Blue Hot Wheels cars from 1980", etc.
15. Any instance of collectible in collection will have its own attributes (lot attributes) that are separate from the collectible's attributes. Lot attributes will be used to track the collectible's value, purchase price, selling price, condition, etc. For example, one user may have Hot Wheels "Ferrari 250 GTO" model, and he may have 10 of them. All 10 are same collectible, but they are instances of it. Each of them will have its own lot attributes (one can be carded, other one loose, etc.). This is important for tracking profitability when selling. So one instance may be mint condition, other one in bad condition, etc. Each collectible instance can have its origin - where it was acquired, when, from whom, for what price, etc. This is important for tracking profitability when selling. Each collectible instance can also be marked as for trade, for sale, or for exchange, or for gift, etc. It can also have its own images that are separate from the collectible's images. These images will be used to showcase the condition of the collectible to potential buyers or traders. These images will also need admin approval to be visible to other users. Admin can reject them for any reason, for example if they are not showing the condition of the collectible, if they are low quality, if they are not showing the collectible properly, they are suspected fakes, etc.
16. Lot attribute "For Sale" will be visible only to collector who owns the collectible. Other users will not be able to see this attribute. If collector decides to sell the collectible, he will need to create a listing for it.
17. All listings are published by collector from their collections and approved by site Admin. Collectors can manage only their own listings.
18. Admin or collector and organize "open markets" that will be conducted in public places designated by Admins. For example TC Usce, Trg Republike, ... Admins are not responsible about what happens in such gatherings ( we need good legal background on this).
19. Ideally, for each listing for sale, LLM AI will analyze the set of images and determine if it is a fake and estimate the condition. Then web scrapers will go and find a current market value in different marketplaces. LLM AI will also suggest the price range to collector. It will not be obligatory just advisory price range.
20. When scraper is scanning for market value, it will intelligently determine the market price based on active ads and their recent history.
